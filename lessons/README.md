# Файли для копіювання

Уся конфігурація живе в одній теці — `cluster/` — з одним воркспейсом і одним
станом. Тут лежать файли, які ви копіюєте туди по мірі просування курсу.

```bash
cp lessons/09-flux/*.tf cluster/
```

| Тека | Коли | Що додає |
|---|---|---|
| `09-flux/` | заняття 9 | провайдер helm, Flux і синхронізацію застосунку з git |
| `extra-metrics-server/` | за бажанням, після 09 | metrics-server для `kubectl top` |

## Чому файли копіюються, а не лежать у cluster/ з початку

Провайдер `helm` налаштовується на кластер, який уже має існувати. Коли ви
копіюєте файли на занятті 9, кластер піднятий і його адреса відома зі стану.
Якби вони лежали в `cluster/` від першого дня, перший `plan` на порожньому
акаунті не зміг би налаштувати провайдер.

Тому, якщо колись знищите все й будуватимете з нуля:

```bash
terraform apply -target=module.eks    # спершу сам кластер
terraform apply                       # потім усе інше
```
